# The example app opts in to the UIKit scene lifecycle for Xcode 27

Building the example app with Xcode 27 (the iOS 27 SDK) produced an immediate launch crash — `EXC_BREAKPOINT` inside UIKit's `_UIApplicationEvaluateRuntimeIssueForNoSceneLifecycleAdoption`, with the underlying message "Application failed to launch: UIScene life cycle is required for apps built with this SDK." This is not a bug in this library: `DatetimePickerPrompt.swift`'s `topViewController()` already looks up the presenting controller via `UIApplication.shared.connectedScenes`, not a legacy `UIApplication.shared.keyWindow`. The crash is at the *host app* level — Apple warned at WWDC25 that the SDK released after iOS 26 would make UIScene adoption mandatory rather than a runtime warning (TN3187), and the example app's Expo SDK 57 template still opened a bare `UIWindow` directly in `AppDelegate.didFinishLaunchingWithOptions`, with no `UIApplicationSceneManifest` in `Info.plist` at all.

Expo's own fix for this gap (shipped in `expo-build-properties` ≥ 57.0.20, usable from Expo ≥ 57.0.23 — this repo is on 57.0.26) is the `ios.enableSceneSupport` build property. It's opt-in rather than default for SDK 57, specifically so existing SDK 57 projects aren't forced into a native-startup change they didn't ask for; SDK 58 makes scene adoption the default and the property becomes a no-op there. The example app now sets:

```json
"plugins": [["expo-build-properties", { "ios": { "enableSceneSupport": true } }]]
```

Turning this on changes two generated files via `expo prebuild`: `Info.plist` gains a `UIApplicationSceneManifest` pointing at Expo's own `EXExpoAppSceneDelegate`, and `AppDelegate` is made to conform to `ExpoReactNativeFactoryProvider` instead of building `window` itself inline. That second part matters — a scene manifest *without* it is a known trap: the app stops crashing but shows a blank screen, because the `UIWindow` built in `AppDelegate` is never attached to the `UIWindowScene` the system actually created. Conforming to `ExpoReactNativeFactoryProvider` hands `window`/`reactNativeFactory`/`reactNativeDelegate` to `EXExpoAppSceneDelegate`, which builds the window from the scene instead. Verified on-device: launched clean on the local Xcode 27.0 / iOS 27.0 simulator after `expo prebuild --clean --platform ios`, where it previously trapped at launch before this change.

This only fixes the **example app**. Any consumer of this library — Expo or bare React Native — hits the identical crash on Xcode 27 unless *their* app has adopted the scene lifecycle; nothing this library does internally can paper over a host app's own `AppDelegate`/`Info.plist`. Expo apps on SDK 57 have the same `enableSceneSupport` flag available; bare React Native apps currently have no official upstream fix (see the open `facebook/react-native` issue and RFC tracked from the README) and need a hand-rolled `SceneDelegate` or a third-party shim in the meantime. See the README's troubleshooting note for what to tell a consumer who reports this.
